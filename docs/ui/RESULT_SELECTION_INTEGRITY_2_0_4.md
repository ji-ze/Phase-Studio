# Result Selection integrity and real ochlor handoff — 2.0.4

Branch: `development/2.0.4`. Existing uncommitted work was preserved. No new
distribution, installer, version, commit, push, tag or publication was created.

## Findings and root causes

The described screenshot patterns can be reproduced by the preceding acceptance
capture script, `capture_results_204.py`:

- It deliberately selects SharpED row 0 after capturing the recommended row.
  Thus Cycle 1 highlighted beside a Cycle 3 star is a manual-selection capture,
  not evidence by itself of an initial-selection failure.
- Its diagonal rows come from `large_cif(40/44)` and an explicitly generated
  collinear fixture. The 44-site CIF was paired with a copied two-site model to
  demonstrate count presentation. That synthetic pair is **not scientific
  evidence** that those 44 detected carbon sites produced that Jana model.
- Its empty screenshot directly assigned `view.selected=None` while leaving
  the Qt table row highlighted. The old implementation allowed this divergent
  state. The duplicate empty messages were separate metadata/canvas labels.
- Its fallback text was manually injected with “Select a completed …”, even
  though Superflip was already selected. The live fallback used similar wording.

Inspection also found real latent defects independent of those capture steps:

1. Initial choice favored `recommendation.selected_candidate`, or the first
   row, without separately ranking handoff-ready candidates.
2. A first automatically initialized selection was saved as though it were an
   explicit manual choice. A later reopening could restore an unready old row
   instead of initializing the best currently ready candidate.
3. Missing-map rows were discarded before the UI, losing their legitimate
   metrics. Missing geometry did not consistently disable viewer controls.
4. Callback checking covered run/source/map and request identity, but not the
   returned threshold and the original completed generation still in the row.

No stale real-project model was found. The real two-threshold test below proves
that identical constrained Jana models can legitimately arise from different
fresh EDMA detections. No scientific ranking or detection formula was changed.

## Corrections

`result_selection.py` now exposes an immutable `CandidateSelection` snapshot:
candidate, readiness, geometry availability, pending state and reason. Its
identity contains run, family, cycle, candidate ID, map SHA, completed threshold,
CIF SHA and M40 SHA. Candidate ID + threshold + artifact hashes identify the
completed generation without adding a serialized scientific field.

The selected Qt row indexes the one candidate registry; `view.selected` is a
property over that row, not an independent stored candidate. Clearing it clears
the highlight. Preview, controls, counts, summary and publication derive from
the same immutable candidate. File hashes are checked using the existing
stat-keyed artifact hash cache; no output is regenerated by readiness checks.

Initialization ranks the ready subset using the **unchanged existing ranking**.
The star/recommended-cycle field retain the scientific recommendation. If that
winner lacks a completed model, the highest-ranked ready row is selected and
the difference is explained. Explicit cycle/family choices alone are restored
on reopening; a new run does not inherit them. Async completion does not reset
the user's row. Wrong run/map/request, wrong threshold and obsolete completed
generation callbacks are rejected.

Combined runs with no ready SharpED model initialize a ready Superflip fallback.
First automatic fallback says it was selected instead; returning to the same
fallback or selecting it manually uses neutral “The selected … can be passed”
wording. Explicit inspection of an incomplete SharpED row remains possible.

An optional UI-only `include_unavailable` registry mode retains metrics-only
rows. The default registry output remains unchanged; it neither recalculates
metrics nor changes their values. Missing geometry displays one canvas message,
a specific reason, a nonempty “No result is ready …” summary and visibly disabled
geometry/EDMA/handoff controls. Map-only export and intentionally EDMA-disabled
Jana continuation retain their existing semantics.

Pass revalidates the snapshot and keeps the dialog open if an artifact changed.
The caller also rejects a forced Accepted result with no ready snapshot. No
candidate is silently substituted at publication. M50/project context and actual
M80/M81 output validation remain in the established publication transaction.
The viewer heading is consistently **STRUCTURE PREVIEW**.

## Real project numerical acceptance

`packaging/tools/audit_selection_handoff_204.py` ran the installed EDMA and real
Superflip format conversion on existing ochlor Cycle 3 maps. It copied only
needed Jana context into `build/selection-integrity-real/`, used the current
normal 0.75 Å merge setting, and verified every original project file's SHA
afterward. No SharpED inference or new phase search was submitted.

Every M40/COO was verified freshly written after its threshold-specific process
started. The actual production handoff transaction published into these isolated
Jana project copies. Full results, paths, byte sizes, hashes, lineage and
alignment diagnostics are in `build/selection-integrity-real/acceptance.json`;
each case has its own `audit.log` and `density_alignment.json`.

The two independently generated SharpED M40 files have the same SHA-256
`0006a6fc3e30e8ec4a29c161ce54bd34b30965ca2bb0ec040219a0390676bf7a`.
This is the unchanged composition-constrained `numberofatoms composition`
selection, not an old model substituted by the UI. Each published M40 is
byte-for-byte identical to its selected completed source: labels, coordinates,
occupancies and displacement records are preserved.

Model coordinates match raw EDMA peak coordinates through the actual P21/n
symmetry to at most **2.1e-15 Å**. The reduced CIF can choose another retained
representative within its merged group: the SharpED maximum distance is
**0.527 Å**, inside the configured **0.75 Å** merge distance. This distinction is
not an origin shift and was not “fixed” by moving atoms or inventing bonds.

The existing `5e-4` density/Fourier acceptance bounds were used unchanged.
Sampling and axis orientation were checked by the production validator. The
real cell is nonorthogonal (β=92.58°) and nonsymmorphic P21/n.

All cases produced a valid, nonzero 767-byte canonical M50, a 13,885,200-byte
M80 and a 700,416-byte M81. The 12-site selected M40 files were 1107 bytes
(SharpED) / 1105 bytes (Superflip), passed the actual declared `writem40`
filename. The post-import `outputbase.m40` is deliberately owned by Jana,
not fabricated by copying raw EDMA under the wrong name.

Uiso ranges were **0.010–0.081025 Å²** (SharpED) and **0.068807–0.150 Å²**
(Superflip). Biso/Uiso conversion and safety policy were not modified.
